## 📕 二、 小红书图文铁律（四大防翻车红线）

### 1. 标题红线：严格 ≤ 20 字符
* **平台规则**：超过 20 字符直接弹窗阻止发布！
* **工程规范**：建议长度为 **16 ~ 19 字符**（包含标点与 Emoji），多留 1 字符安全边距。

### 2. 正文红线：实测全量字符 ≤ 850 字符
* **暗坑警示**：小红书后台字数统计包含**所有回车换行符 `\n`、空格、标点和 Emoji**！
* **工程规范**：虽然官方上限标称 1000 字符，但编写时必须用脚本计算全量字符严格控制在 **≤ 850 字符**以内，预留 150 字符缓冲，杜绝因排版空行过多触发 1000 字符截断。

### 3. 图片规格：强制 `1152x1536`（严格 3:4 满屏比）
* **黑边之谜**：小红书移动端展示视口按 3:4 锁死在 632px 高度。若误传 `1024x1536 (2:3)`，画面会因为过高而被等比压窄至 421px，**左右两边被强制塞入各 26.5px 黑边 (Letterboxing)**！
* **工程规范**：
  * 分辨率必须指定为 **`1152x1536`**（两边均为 16 的整倍数：$72 \times 96$），天生 100% 满屏无黑边！
  * 采用 **Full-Bleed（满幅出血排版）**，大标题横向撑满左右两端，严禁卡片套卡片式的三重缩放留白。

### 4. 资产隔离：单篇文章独立专属目录
* **工程规范**：每篇小红书笔记的图片必须隔离在 `assets/images/xiaohongshu/<date-slug>/` 专属目录下，严格保序命名为 `p01-cover.png`, `p02-xxx.png` ... `p09-xxx.png`。
* **发布操作**：终端执行 `open "目录路径"`，在 Finder 中按 `Cmd+A` 全选，直接拖入小红书创作者后台。

## 💻 三、 极客长文多平台自动同步规约 (WechatSync 桥接)

### 1. 架构原理
* **零中转、本地直推**：直接以本地 `03-articles/drafts/` 下的 Markdown 文件为源头，通过本地 WebSocket (:9527) 与 Chrome 扩展通信，利用浏览器中已登录的 Cookie 直接调用各大平台的官方创作接口写入**草稿箱**。
* **零封号风险**：完全走正常用户身份，无需明文密码，不触发平台风控。

### 2. 发布前环境自检清单 (Pre-flight Checklist)
每次执行自动同步前，确保满足以下三项物理条件：
1. **Chrome 浏览器已启动**；
2. **WechatSync 扩展设置**：已开启【CLI / MCP 连接】开关（绿色），Token 与本地 `.env` 中的 `WECHATSYNC_TOKEN` 保持一致；
3. **目标平台登录态**：在 Chrome 中确认掘金、知乎、CSDN 等目标平台处于正常登录状态。

### 3. 命令行标准发布姿势
```bash
# 1. 探测各平台登录态
python3 .agents/skills/article-publisher/scripts/publish.py list

# 2. 一键直推各大平台草稿箱（自动上传本地图片至图床 + 自动转存）
python3 .agents/skills/article-publisher/scripts/publish.py sync \
  "03-articles/drafts/YYYY-MM-DD-[slug].md" \
  -p juejin,zhihu,csdn,cnblogs,imooc \
  -c "assets/images/articles/[slug]/cover.png"
```

## 🛡️ 四、 软件工程与人设边界铁律

1. **底层技能纯洁性（OCP 原则）**：
   * `gpt-image-gen` 是跨项目通用的基础设施，严禁硬编码具体平台的业务偏好；
   * 业务参数（如小红书专属的 `-s "1152x1536"`）必须由上层业务流水线（`article-gen` / 本项目 rules）在调用时显式传参。
2. **对外技术文章人设隔离**：
   * 对外正式发布的技术文章，作者署名固定为 **佳欣的AI工坊 (@ljxpython)**；
   * 严禁在正式文章正文中出现 Agent 的口吻（如“老王看到必回”等代入痕迹），保持专业、严谨、克制的技术沉淀风格。
